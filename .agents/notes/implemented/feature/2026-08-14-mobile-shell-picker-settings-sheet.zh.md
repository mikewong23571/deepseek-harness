# Agent Note: 移动端外壳：下拉选择器、portal 设置表单与纯图标导出

Status: implemented

[English](2026-08-14-mobile-shell-picker-settings-sheet.md) | 中文

## Problem

在布局 1024px 自动收起断点以下，Web 外壳没有针对性的移动端设计：桌面三栏框架被挤压成不可用的轨道，设置面板完全无法绘制，Session Header 的导出胶囊还把宝贵的宽度花在文字标题上。第一版适配把整个侧边栏作为左侧滑出抽屉挂在页头切换器之后，但为了回答「我在哪个会话、我要去哪个会话」而拉出整根导航栏——品牌行、轨道、设置页脚——超出了这个手势的需要：切换器是选择动作，应该呈现选择界面。

## Decision

**移动端框架是「两行网格 + 下拉选择器」，不是抽屉。** 断点以下，AppFrame 渲染全宽顶部页头（当前会话标题切换器加设置齿轮）和全宽会话区；`sidebar` slot 脱离网格流，挂载为页头下方的固定下拉面板，沿用轨道切换所用的 `narrowExpanded` 覆盖状态开合，点遮罩、选中会话或点击设置齿轮即关闭。侧边栏 owner share 新增 `picker` 标志；picker 模式下的 SidebarRoot 只渲染「新建会话」按钮和始终为 wide 的 `sidebar.workspaces` 浏览区——不再有品牌行、轨道或页脚——并以不可见方式保持 `sidebar.settings` 席位挂载，使其 portal 面板始终可达（卸载它会让页头齿轮写入一个无人渲染的 store）；下拉的开合由框架持有，子树保持挂载。

**设置面板经 portal 挂到 `document.body`。** 内联渲染时，面板的 fixed 定位会被侧边栏下拉容器的 transform 收容，裁剪进下拉盒内——这正是移动端设置无法展示的具体原因。portal 也让桌面面板不再受未来任何祖先 transform 影响。断点以下，对话框变为全屏表单：188px 导航轨道转为内容上方可横向滚动的分区条，面板标题让位于分区条（display:none 的节点仍参与 aria-labelledby 的名称计算）。面板开合状态是一个共享 store，侧边栏触发控件和页头齿轮（经 `ctx.layout.openSettings` / `onOpenSettings` 发信号）写的是同一个开关，一个面板服务两个入口。

**Session Header 的导出操作纯图标化，并在移动端缺席。** 111×32 的 `Session log` 胶囊改为 32px 图标按钮，本地化名称由 tooltip 和 aria-label 承载；断点以下按钮完全退出页头，低频的 `/export` 命令仍是入口，依旧由同一个控制器和结果弹窗支持。

## Alternatives considered

**保留左侧滑出抽屉。** 否决：切换器手势要的是选择会话，不是整根导航栏；抽屉还把品牌行和设置页脚带进了一个与页头齿轮重复的表面。

**移动端设置采用两页式流程（导航页，再带返回的分区页）。** 暂不采纳：相对内容量而言状态机成本过高；横向分区条让切换分区始终一次点击可达，不需要导航栈，也没有返回转场。

**在picker内注册一个移动端专用的导出入口。** 否决：导出在移动端是低频手势；`/export` 命令路径已经到达同一个控制器和弹窗，再设一个移动端席位只会增加表面而不增加能力。

**把选择器移出 slot 树，由布局自绘会话列表。** 否决：项目/会话浏览是 ui-workspace 的业务，经 `sidebar.workspaces` 渲染；在 ui-layout 里重写会重复 slot 系统已经组合好的分组、搜索和弹窗逻辑。

## Consequences

移动端获得了可用的设置界面、一键会话切换器和更精简的页头；桌面端只有导出按钮的标题变化（图标加 tooltip）。选择器沿用既有的折叠覆盖 store 标志，因此跨越断点的两个方向都会重置它。`sidebar.footer.action` 席位在移动端不渲染，其 occupant（目前是开发期面板）在设计出席位前仅桌面可用。Web e2e 套件的 aria golden 从带标题的胶囊变为带标签的图标按钮，已在同一变更中刷新。
